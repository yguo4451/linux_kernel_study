# 07 三次握手的内核实现（服务端被动打开）

从"QEMU 里看到 ESTABLISHED"追到内核源码，看一个 SYN 包如何走完三次握手。

## 完整调用链

```
客户端 SYN 到达
  → tcp_v4_rcv            (net/ipv4/tcp_ipv4.c:1993)  收包入口，__inet_lookup_skb 找到 LISTEN socket
  → tcp_v4_do_rcv         (tcp_ipv4.c:1708)            状态分派
  → tcp_rcv_state_process (tcp_input.c:6531)           状态机
    → case TCP_LISTEN + th->syn  (tcp_input.c:6546)
      → icsk->icsk_af_ops->conn_request = tcp_v4_conn_request (tcp_ipv4.c:1538)
        → tcp_conn_request (tcp_input.c:6986)
          - inet_reqsk_alloc：分配 request_sock（半连接）
          - inet_csk_reqsk_queue_hash_add：进半连接队列
          - send_synack：回 SYN-ACK（第二次握手）
客户端回 ACK（第三次握手）
  → tcp_check_req 取出 req → 创建 child socket → accept 队列
  → tcp_set_state(sk, TCP_ESTABLISHED)  (tcp_input.c:6657)
应用 accept() → 从 accept 队列取出 child socket
```

## 关键源码

### ① LISTEN 分支处理 SYN（tcp_input.c:6546）

```c
case TCP_LISTEN:
	if (th->ack) return 1;
	if (th->rst) goto discard;
	if (th->syn) {
		if (th->fin) goto discard;
		rcu_read_lock();
		local_bh_disable();
		acceptable = icsk->icsk_af_ops->conn_request(sk, skb) >= 0;
		local_bh_enable();
		rcu_read_unlock();
		if (!acceptable) return 1;
		consume_skb(skb);          // SYN 被吃掉，不上交用户态
		return 0;
	}
```

### ② 回 SYN-ACK（tcp_input.c:6986）

```c
int tcp_conn_request(...)
{
	req = inet_reqsk_alloc(rsk_ops, sk, !want_cookie);   // 半连接 request_sock
	tcp_openreq_init(req, &tmp_opt, skb, sk);
	if (!want_cookie) {
		req->timeout = tcp_timeout_init(...);
		inet_csk_reqsk_queue_hash_add(sk, req, req->timeout);  // 进半连接队列
	}
	af_ops->send_synack(sk, dst, &fl, req, &foc, ..., skb);    // 回 SYN-ACK
}
```

### ③ 第三次 ACK → ESTABLISHED（tcp_input.c:6626）

```c
case TCP_SYN_RECV:
	tp->delivered++;
	if (!tp->srtt_us)
		tcp_synack_rtt_meas(sk, req);   // 量 SYN-ACK 往返 RTT
	...
	tcp_set_state(sk, TCP_ESTABLISHED);  // 握手完成
	sk->sk_state_change(sk);
```

## 核心设计：为什么用 request_sock（半连接）

| 设计 | 原因 |
|---|---|
| 收到 SYN 不建完整 socket，只建轻量 request_sock | 完整 struct sock 很大（收发缓冲、拥塞控制状态），SYN flood 会瞬间耗尽内存 |
| 只有收到合法 ACK 才建完整 child socket | 半连接是低成本试探，ACK 证明对端真实存在 |
| 半连接队列有上限 + SYN cookie | 队列满时不存 req，把连接信息编码进 SYN-ACK 序号，ACK 回来再解码 |

SYN flood 防护（tcp_input.c 约 6910）：

```c
if ((syncookies == 2 || inet_csk_reqsk_queue_is_full(sk)) && !isn) {
	want_cookie = tcp_syn_flood_action(sk, rsk_ops->slab_name);
	if (!want_cookie)
		goto drop;
}
```

## 两个队列

```
收到 SYN   → request_sock 进「半连接队列」(syn queue)
回 SYN-ACK
收到 ACK   → 取 req → 创建 child socket → 进「全连接队列」(accept queue)
accept()   → 从全连接队列取出 → 新 fd
```

`listen()` 的 `backlog` 参数限制的是全连接队列长度。

## 与实验现象对应

服务端 `nc -l` 还没 accept，`/proc/net/tcp` 已出现 st=01(ESTABLISHED)——因为三次握手在内核态完成，child socket 已 ESTABLISHED 并躺在 accept 队列，等应用 accept。
