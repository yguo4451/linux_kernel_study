# NAT 网络地址转换原理

**NAT = Network Address Translation（网络地址转换）**。一句话：让一堆使用私有地址的机器，共用一个公网地址上网。

## 1. 为什么需要 NAT：私有地址上不了公网

IPv4 只有 42 亿个地址，早不够用了。于是划了三段私有地址（RFC 1918），仅供内网使用：

| 网段 | 范围 |
|---|---|
| 10.0.0.0/8 | 10.0.0.0 ~ 10.255.255.255 |
| 172.16.0.0/12 | 172.16.x ~ 172.31.x |
| 192.168.0.0/16 | 192.168.x.x |

关键规则：公网路由器看到私有地址的包，直接丢弃。所以 `10.0.2.15` 这样的地址，光靠自己是上不了公网的。NAT 就是解决这个问题的翻译官。

## 2. 源地址转换（SNAT，出方向）

内网机器发包出去时，NAT 网关把源 IP 换成自己的公网 IP：

```
内网 10.0.2.15 ──► NAT 网关 ──► 公网服务器 8.8.8.8
   源:10.0.2.15         源:203.0.113.5        （网关的公网IP）
```

回包时再反向翻译：网关把目标 IP 换回 10.0.2.15，送进内网。

## 3. 端口映射（PAT / NAPT，多机共用一个 IP）

内网几十台机器共用一个公网 IP，回包怎么区分该给谁？用端口号：

```
内网机器A 10.0.2.15:12345 ──┐
                            ├─► 网关公网 203.0.113.5 各用不同源端口出去
内网机器B 10.0.2.16:12345 ──┘
```

网关维护一张映射表（连接跟踪表 conntrack）：

```
内网源              →  公网源（网关代发）
10.0.2.15:12345     →  203.0.113.5:50001
10.0.2.16:12345     →  203.0.113.5:50002
```

回来的包 `203.0.113.5:50001`，查表 → 转发给 `10.0.2.15:12345`。这就是 PAT（端口地址转换），家用路由器最常用模式。

## 4. 为什么外网"看不到"内网机器

三层原因：

1. 外网只看到网关的公网 IP，不知道私有地址的存在
2. 映射表只有"内网主动发起"才有条目；外网凭空发来的包查不到映射 → 丢弃
3. 所以 NAT 天然是一道"防火墙"：默认挡住所有入站连接

## 5. 反向：端口转发（DNAT，入方向）

想让外网主动访问内网机器，需手动加映射——端口转发：

```
外网访问 203.0.113.5:8080 → 网关 DNAT → 转发给内网 10.0.2.15:80
```

QEMU 对应参数：

```bash
-netdev user,id=n0,hostfwd=tcp::8080-:80   # 宿主机 8080 → guest 80
```

## 6. QEMU user 网络（slirp）的 NAT 流程

```
guest(10.0.2.15) ping 8.8.8.8
   │  ① ICMP 包，源 10.0.2.15
   ▼
QEMU slirp（用户态 NAT 网关）
   │  ② 源地址换成宿主机 IP
   ▼
宿主机真实网络 → 8.8.8.8
   │  ③ 回包到宿主机 IP
   ▼
slirp 查映射表 → ④ 目标换回 10.0.2.15 → 送达 guest
```

8.8.8.8 从头到尾只和"宿主机 IP"对话，完全不知道 10.0.2.15 的存在。

## QEMU user 网络固定地址表

| IP | 角色 |
|---|---|
| 10.0.2.2 | 网关 |
| 10.0.2.3 | DNS 服务器 |
| 10.0.2.4 | SMB 共享 |
| 10.0.2.15 | 默认 guest IP |
| 10.0.2.255 | 广播地址 |

## 一句话总结

> NAT 用"改源/目的地址 + 端口映射 + 连接跟踪表"三件套，让内网私有地址通过一个公网 IP 上网；代价是外网默认无法主动访问内网（除非端口转发）。它既是"地址翻译官"，也是一道天然的"单向防火墙"。

## 相关概念延伸

- conntrack：Linux 内核的连接跟踪表（`/proc/net/nf_conntrack`）
- iptables NAT 表：`MASQUERADE`（SNAT 变体）、`DNAT`、`SNAT`
- 应用：ECU 网络、车载网关、端口转发场景
