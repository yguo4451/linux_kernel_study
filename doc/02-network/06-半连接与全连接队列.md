# 08 半连接队列与全连接队列（syn queue / accept queue）

TCP 握手最核心的两个队列：半连接队列（request_sock 集合）与全连接队列（accept queue），以及"半连接如何转换为全连接"。

## 一、半连接队列是什么

不是独立数组，而是散落在 ehash 里的 `request_sock`（迷你 sock）。

`include/net/request_sock.h:53`：

```c
struct request_sock {
	struct sock_common	__req_common;   // 只留四元组/哈希等最小字段
	struct request_sock	*dl_next;       // 全连接队列 FIFO 指针
	u16			mss;
	u8			num_retrans;    // SYN-ACK 重传次数
	u8			syncookie:1;
	u8			num_timeout:7;  // 超时次数
	u32			ts_recent;
	struct timer_list	rsk_timer;      // SYN-ACK 重传定时器
	struct sock		*sk;            // 握手完成后指向 child
};
```

`struct request_sock_queue`（`:175`）同时管理两个队列：

```c
struct request_sock_queue {
	atomic_t		qlen;              // 半连接队列长度
	struct request_sock	*rskq_accept_head; // 全连接队列头
	struct request_sock	*rskq_accept_tail; // 全连接队列尾
};
```

**反直觉设计**：全连接队列挂的不是 child sock，而是同一个 request_sock（`dl_next` 串 FIFO），`req->sk` 指向 child。

## 二、半连接队列能做的事

| 职责 | 实现 | 源码 |
|---|---|---|
| 记住协商选项 | MSS/时间戳/窗口缩放/SACK | `tcp_openreq_init` |
| SYN-ACK 重传 | num_retrans + rsk_timer | `inet_csk_reqsk_queue_hash_add` 里 mod_timer |
| 超时丢弃 | num_timeout 超阈值清理 | `reqsk_timer_handler` |
| SYN cookie 兜底 | syncookie:1 不占内存 | `tcp_syn_flood_action` |
| 防 SYN flood | qlen 上限 + synflood_warned | `inet_csk_reqsk_queue_is_full` |

## 三、半连接 → 全连接的转换

第三次 ACK 到达的链路：

```
__inet_lookup_skb（四元组查 ehash 找到 req）
  → tcp_check_req  (net/ipv4/tcp_minisocks.c:599)
      - 纯重传 SYN        → 重发 SYN-ACK
      - ACK 序号错/RST/SYN → 丢弃或发 RST
      - 合法 ACK          → syn_recv_sock 创建 child
  → tcp_v4_syn_recv_sock (tcp_ipv4.c:1557) → tcp_create_openreq_child
  → inet_csk_reqsk_queue_add (inet_connection_sock.c:1325)
      req->sk = child;  req 挂进 rskq_accept_head FIFO
  → child = ESTABLISHED，等 accept()
  → accept() → reqsk_queue_remove (request_sock.h:200) 取 req->sk
```

关键代码：

```c
// tcp_check_req (tcp_minisocks.c) 校验通过后：
child = inet_csk(sk)->icsk_af_ops->syn_recv_sock(sk, skb, req, NULL, req, &own_req);
if (!child)
	goto listen_overflow;   // 全连接队列满
return inet_csk_complete_hashdance(sk, child, req, own_req);

// inet_csk_reqsk_queue_add (inet_connection_sock.c:1325)：
req->sk = child;
req->dl_next = NULL;
if (queue->rskq_accept_head == NULL)
	WRITE_ONCE(queue->rskq_accept_head, req);
else
	queue->rskq_accept_tail->dl_next = req;   // FIFO 尾插
queue->rskq_accept_tail = req;
sk_acceptq_added(sk);

// reqsk_queue_remove (request_sock.h:200) accept 取队头：
req = queue->rskq_accept_head;
WRITE_ONCE(queue->rskq_accept_head, req->dl_next);
```

## 四、一个 req 的一生

```
收到 SYN     req 插入 ehash（半连接）     req->sk = NULL
回 SYN-ACK   num_retrans 计时重传
收到 ACK     tcp_check_req 校验
              └→ syn_recv_sock 创建 child
              └→ req->sk = child
              └→ req 摘出 ehash，挂进 rskq_accept_head（全连接）
accept()     取 rskq_accept_head 的 req，返回 req->sk = child
```

**核心洞察**：request_sock 贯穿两个阶段——先是"半连接记录"，握手完成后变身"全连接队列节点"（dl_next 串起来、sk 指 child）。用极简内存完成半连接→全连接转换。

## 附：不是读写缓冲区

半连接/全连接队列**不是**读写缓冲区，虽然都共享"缓冲"思想：

| | backlog 队列 | 读写缓冲区 |
|---|---|---|
| 缓冲对象 | 连接（request_sock/sock） | 数据字节（sk_buff） |
| 单位 | 个 | 字节 |
| 控制 | listen() backlog | SO_SNDBUF / SO_RCVBUF |
| 消费方 | accept() | read() / write() |
| 阶段 | 连接建立 | 数据传输 |
| 字段 | icsk_accept_queue | sk_sndbuf / sk_rcvbuf / sk_receive_queue |

一句话：**backlog 队列是"连接级"缓冲，读写缓冲区是"字节级"缓冲。**

面试高频陷阱：`listen()` 的 backlog 限制的是**全连接队列长度**（已完成握手、等 accept 的连接数），不是收发缓冲区大小。

### 读写缓冲区何时创建

分两层，时机不同：

| 层次 | 是什么 | 何时创建 |
|---|---|---|
| 额度字段 | sk_sndbuf / sk_rcvbuf（字节上限） | socket() 创建时（CLOSE 状态） |
| 实际内存 | sk_buff 队列 | 按需分配，收发数据时才分配 |

时间线：

```
① socket()  [CLOSE]
   sock_init_data_uid (net/core/sock.c:3427)：
     sk->sk_rcvbuf = sysctl_rmem_default; sk->sk_sndbuf = sysctl_wmem_default
② tcp_init_sock (net/ipv4/tcp.c:458)：
     sk->sk_sndbuf = tcp_wmem[1]=16KB; sk->sk_rcvbuf = tcp_rmem[1]=128KB
③ ESTABLISHED：tcp_init_buffer_space → tcp_sndbuf_expand 按 MSS×cwnd 扩容额度
④ 数据传输：
     发送 sk_stream_alloc_skb 分配 skb，sk_wmem_queued 累加（受 sk_sndbuf 限）
     接收 sk_rmem_schedule 分配 skb，sk_rmem_alloc 累加（受 sk_rcvbuf 限）
```

三个洞察：

- **socket() 便宜**：只初始化几个 int 字段，不分配数据内存
- **额度 ≠ 已用**：sk_sndbuf/sk_rcvbuf 是上限，实际用量看 sk_wmem_queued/sk_rmem_alloc 计数器
- **额度自调整**：发送 tcp_sndbuf_expand、接收 tcp_rcv_space_adjust 动态 autotuning
