# 09 数据快速路径：tcp_rcv_established 的头部预测

ESTABLISHED 状态收包主函数 `tcp_rcv_established`（tcp_input.c:5922）分 fast path 与 slow path。本文聚焦 fast path。

## 一、整体结构

```
收到数据包
  ├─ 命中头部预测 → fast path：跳过大部分校验，直接处理
  └─ 未命中       → slow path：RFC793 完整流程
```

## 二、fast path 三个判定条件（tcp_input.c:5961）

```c
if ((tcp_flag_word(th) & TCP_HP_BITS) == tp->pred_flags &&  // ① 头部标志匹配预测
    TCP_SKB_CB(skb)->seq == tp->rcv_nxt &&                  // ② 按序到达
    !after(TCP_SKB_CB(skb)->ack_seq, tp->snd_nxt)) {        // ③ ACK 未确认未发送数据
```

- ① pred_flags 匹配：包的 TCP 头 = 预测的样子（头长+ACK+窗口）
- ② seq == rcv_nxt：无乱序
- ③ ack_seq <= snd_nxt：ACK 没提前确认

## 三、pred_flags：头部预测核心（include/net/tcp.h:700）

```c
tp->pred_flags = htonl((tp->tcp_header_len << 26) |
		       ntohl(TCP_FLAG_ACK) |
		       snd_wnd);
```

提前猜下一个包的 TCP 头。`tcp_fast_path_check`（tcp.h:716）决定何时开启：

```c
if (RB_EMPTY_ROOT(&tp->out_of_order_queue) &&  // 无乱序
    tp->rcv_wnd &&                             // 窗口非零
    atomic_read(&sk->sk_rmem_alloc) < sk->sk_rcvbuf &&  // 接收缓冲没满
    !tp->urg_data)                             // 无紧急数据
	tcp_fast_path_on(tp);
```

## 四、fast path 两种场景

**纯 ACK 包（len == tcp_header_len）→ bulk sender**：

```c
tcp_ack(sk, skb, 0);        // 推进 snd_una（跳过校验和，入口已验）
__kfree_skb(skb);
tcp_data_snd_check(sk);     // 窗口开就继续发
```

**带数据包（len > tcp_header_len）→ bulk receiver**：

```c
NET_INC_STATS(sock_net(sk), LINUX_MIB_TCPHPHITS);
__skb_pull(skb, tcp_header_len);
eaten = tcp_queue_rcv(sk, skb, &fragstolen);   // 数据直接入接收队列
tcp_event_data_recv(sk, skb);
tcp_data_ready(sk);                            // 唤醒 read
```

## 五、为什么快

跳过校验和（纯 ACK）、跳过状态机、头部预测一个 if 替代多次判断、零拷贝、简化序号检查。

## 六、何时退化 slow path（源码注释 7 种）

零窗口 | 乱序 | 紧急数据 | 缓冲不足 | pred_flags 不匹配 | 双向传输 | 意外 TCP 选项。

## 七、slow path（RFC793 全流程）

```c
slow_path:
	if (len < (th->doff << 2) || tcp_checksum_complete(skb)) goto csum_error;
	if (!tcp_validate_incoming(sk, skb, th, 1)) return;   // PAWS+序号+RST+SYN
step5:
	tcp_ack(sk, skb, FLAG_SLOWPATH | FLAG_UPDATE_TS_RECENT);
	tcp_urg(sk, skb, th);
	tcp_data_queue(sk, skb);    // 处理乱序/SACK/out_of_order_queue
	tcp_data_snd_check(sk);
	tcp_ack_snd_check(sk);
```

## 八、架构洞察

统计优化思想（同 CPU 分支预测）：多数包"按序、纯 ACK、窗口不变"，用头部预测走最短路径，异常落慢路径。

`LINUX_MIB_TCPHPHITS` = fast path 命中计数，`/proc/net/netstat` 的 TcpExt 里可见 `TCPHpHits`。


## 实验：用 /proc/net/netstat 验证 fast path

`/proc/net/netstat` 的 TcpExt 是 TCP 统计的黑匣子。字段名和数值分两行，用 awk 对齐：

```sh
awk '/^TcpExt:/{if(!n){for(i=2;i<=NF;i++)nm[i]=$i;n=1}
     else{for(i=2;i<=NF;i++)if($i!=0)printf "%s=%s\n",nm[i],$i}}' /proc/net/netstat
```

传 200KB 数据前后对比（回环 nc）：

| 统计项 | 基线 | 传后 | 对应源码 |
|---|---|---|---|
| TCPPureAcks | 5 | 25 | tcp_ack 里 LINUX_MIB_TCPPUREACKS（纯 ACK） |
| TCPOrigDataSent | 4 | 27 | 发送路径原始数据段 |
| TCPDelivered | 5 | 29 | tcp_newly_delivered → TCPDELIVERED |
| TCPRcvCoalesce | 0 | 5 | tcp_try_coalesce 接收侧 skb 合并 |
| TW | 2 | 3 | tcp_time_wait |

实测（用户 QEMU，200KB 传输）：

- `TCPPureAcks` 5→25（+20）：每个纯 ACK 命中 fast path `len == tcp_header_len` 分支（bulk sender）
- `TCPDelivered` +24：24 个数据段被确认投递
- `TCPRcvCoalesce` 0→5：接收队列里序号连续的 skb 合并 5 次（tcp_try_coalesce，省内存）

`TCPPureAcks` / `TCPDelivered` 飙升 = fast path 正在工作（bulk sender 场景命中）。

关键统计项速查：

- `TCPHPHits`：fast path 带数据分支命中（bulk receiver）
- `TCPPureAcks`：纯 ACK 包（seq==end_seq）
- `TCPHPAcks`：fast path 内窗口不变的 ACK
- `ListenOverflows` / `ListenDrops`：全连接队列溢出/丢弃（对应 doc/08）
- `TCPReqQFullDoCookies` / `TCPReqQFullDrop`：半连接队列满 → 发 cookie / 丢弃
