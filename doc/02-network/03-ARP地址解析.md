# ARP 地址解析协议

ARP = Address Resolution Protocol（地址解析协议）。解决一个问题：**知道 IP（三层地址），但发以太网帧需要 MAC（二层地址），中间缺翻译。**

## ARP 缓存表

```sh
arp -a
# ? (10.0.2.2) at 52:55:0a:00:02:02 [ether] on eth0
```

字段含义：

| 字段 | 含义 |
|---|---|
| `?` | 主机名无法反查（无 DNS PTR） |
| `10.0.2.2` | 目标 IP |
| `52:55:0a:00:02:02` | 目标 MAC |
| `[ether]` | 硬件类型：以太网 |
| `on eth0` | 从哪个接口学到 |

## 工作流程

```
发数据给 10.0.2.2
  ├─① 查 ARP 缓存：有没有 10.0.2.2 的 MAC？→ 没有
  ├─② 广播 ARP 请求："谁是 10.0.2.2？"
  ├─③ 目标单播回复："我是，MAC = xx:xx:xx:xx:xx:xx"
  ├─④ 存入缓存表
  └─⑤ 之后直接用 MAC 发帧，不再广播
```

## QEMU slirp 的 MAC 彩蛋

网关 10.0.2.2 的 MAC 是 `52:55:0a:00:02:02`——后四段 `0a:00:02:02` 正是 `10.0.2.2` 的十六进制。slirp 把 IP 编码进 MAC，方便调试。

两个 MAC 前缀区分：

| MAC | 是谁 |
|---|---|
| `52:54:00:...` | virtio-net 网卡设备自身 |
| `52:55:...` | slirp 虚拟主机（网关/DNS），IP 编码在后四字节 |

## 常用命令

```sh
arp -a              # 看缓存表
cat /proc/net/arp   # 内核原始表（更准）
arp -d 10.0.2.2     # 删除某条缓存
ping 10.0.2.2       # 触发重新学习
```

## 关键点

- ARP 缓存**会过期**（几分钟），过期后重新广播问
- ARP 请求是**广播**，应答是**单播**
- ARP 只作用于**同一个二层网段**（跨网段走网关，由网关代答）
- 内核里对应源码：`net/ipv4/arp.c`

## 与 IP 的关系

- IP：三层逻辑地址，跨网段路由
- MAC：二层物理地址，同网段内投递
- ARP：把 IP 翻译成 MAC 的"电话簿"
