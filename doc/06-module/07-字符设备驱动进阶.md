# 27. 字符设备驱动进阶：write / ioctl / 自动建节点

> 阶段四第七课。把只读的字符设备升级成可交互设备：`write` 反向拷贝、`ioctl` 控制命令、`class_create` + `device_create` 自动建节点（告别 mknod）。

## 一、write：反向拷贝（copy_from_user）

与 `read` 对称，方向相反：

```c
static char kernel_buf[128] = "Hello from kernel!\n";   // 唯一数据源

static ssize_t hello_write(struct file *file, const char __user *buf,
                           size_t len, loff_t *off) {
    if (len >= sizeof(kernel_buf)) return -EINVAL;
    if (copy_from_user(kernel_buf, buf, len)) return -EFAULT;  // 用户态 → 内核
    kernel_buf[len] = '\0';
    return len;
}
```

| 方向 | 函数 | 场景 |
|------|------|------|
| 内核 → 用户态 | `copy_to_user` | read |
| 用户态 → 内核 | `copy_from_user` | write |

两个函数第一个参数永远是**用户态指针**。

**设计原则**：一个设备的数据只有一个"真相来源"（single source of truth）。`read` 和 `write` 都读写同一个 `kernel_buf`，不要另搞一份 `msg` 数组，否则容易出现"长度从一个 buffer 算、内容从另一个 buffer 拷"的错乱 bug。

## 二、ioctl：控制命令（unlocked_ioctl）

```c
long (*unlocked_ioctl)(struct file *, unsigned int cmd, unsigned long arg);
```

命令号用 `<linux/ioctl.h>` 宏编码，不手写数字：

```c
#define HELLO_MAGIC 'H'                  // 设备专属魔数
#define HELLO_RESET _IO(HELLO_MAGIC, 0)  // 重置命令，无参数
```

| 宏 | 方向 |
|----|------|
| `_IO(type, nr)` | 无数据 |
| `_IOR(type, nr, 类型)` | 驱动→用户 |
| `_IOW(type, nr, 类型)` | 用户→驱动 |
| `_IOWR(type, nr, 类型)` | 双向 |

驱动侧：

```c
static long hello_ioctl(struct file *file, unsigned int cmd, unsigned long arg) {
    switch (cmd) {
    case HELLO_RESET:
        strncpy(kernel_buf, "Hello from kernel!\n", sizeof(kernel_buf) - 1);
        return 0;
    default:
        return -ENOTTY;   // 不认识的命令，标准返回（不是 -EINVAL）
    }
}
```

用户态测试程序（guest 无现成 ioctl 工具，需自己写，**静态编译**避免 glibc 版本不匹配）：

```c
#include <fcntl.h>
#include <sys/ioctl.h>
#include <stdio.h>
#include <unistd.h>   // close()

#define HELLO_MAGIC 'H'
#define HELLO_RESET _IO(HELLO_MAGIC, 0)

int main(void) {
    int fd = open("/dev/hello_dev", O_RDWR);
    if (fd < 0) { perror("open"); return 1; }
    if (ioctl(fd, HELLO_RESET) < 0) { perror("ioctl"); return 1; }
    close(fd);
    return 0;
}
```

## 三、class_create + device_create：自动建节点

之前手动 `mknod`，现在让内核自动建：

```c
#include <linux/device.h>
static struct class *hello_class;

// init（cdev_add 之后）：
hello_class = class_create("hello_dev");
device_create(hello_class, NULL, dev_num, NULL, "hello_dev");

// exit（cdev_del 之前）：
device_destroy(hello_class, dev_num);
class_destroy(hello_class);
```

机制：

```
class_create("hello_dev")
  → /sys/class/ 下建 hello_dev 目录（归类）

device_create(...)
  → /sys/class/hello_dev/ 下建设备条目
  → 发 uevent → devtmpfs 收到 → 自动在 /dev 建 /dev/hello_dev
```

**前提**：`/dev` 必须是 devtmpfs（本项目 init 里 `mount -t devtmpfs devtmpfs /dev` + 内核 `CONFIG_DEVTMPFS=y`）。

效果：`insmod` 节点自动出现，`rmmod` 节点自动消失，告别 mknod/rm。

## 四、实验验证

```bash
insmod hello_dev.ko
ls -l /dev/hello_dev          # crw------- 510,0（自动出现）
cat /dev/hello_dev            # Hello from kernel!
echo "nice to meet you" > /dev/hello_dev
cat /dev/hello_dev            # nice to meet you
./hello_dev_test              # ioctl RESET
cat /dev/hello_dev            # Hello from kernel!
ls /sys/class/hello_dev/      # hello_dev（class 目录）
rmmod hello_dev
ls -l /dev/hello_dev          # 自动消失
```

## 五、踩坑记录

1. **read/write 数据源混用**：长度从一个 buffer 算、内容从另一个拷，导致输出被截断。
2. **`close` 隐式声明**：用户态测试程序漏 `<unistd.h>`，`-Wimplicit-function-declaration` 警告。
3. **VirtioFS 缓存滞后**：宿主改完文件，容器编译时还看到旧版本（报"文件正确却编译错"）。先 `cat` 确认容器看到的内容，旧了就 `docker restart linux-builder` 或等几秒。
4. **设备节点默认 0600**：`device_create` 默认 mode 是 `0600`（root 可读写），非 root 用户访问不了。要放开可用 `device_create_with_groups` 或设置 devnode 权限。
5. **ioctl 命令号要两边一致**：驱动和用户态程序用同一个头文件定义，避免魔数不一致。
