# 26. 字符设备驱动：从模块到驱动

> 阶段四第六课。通过 `/dev/hello_dev` 设备实验，理解字符设备驱动的完整机制：`cdev` + `file_operations`、注册三步、设备号、`chrdev_open` 多态落地、`copy_to_user`，并接回 VFS 的 `file->f_op` 多态知识。

## 一、概念：驱动核心是一张函数指针表

字符设备驱动 = 一个模块 + 一张 `struct file_operations`。用户态对 `/dev/xxx` 的每个系统调用，最终转发到这张表。

```c
// include/linux/fs.h:2113
struct file_operations {
    struct module *owner;
    ssize_t (*read) (struct file *, char __user *, size_t, loff_t *);
    ssize_t (*write)(struct file *, const char __user *, size_t, loff_t *);
    long (*unlocked_ioctl)(struct file *, unsigned int, unsigned long);
    int (*mmap) (struct file *, struct vm_area_struct *);
    int (*open) (struct inode *, struct file *);
    int (*release)(struct inode *, struct file *);
    ...
};
```

## 二、关键数据结构：struct cdev

```c
// include/linux/cdev.h
struct cdev {
    struct kobject kobj;
    struct module *owner;
    const struct file_operations *ops;   // ← 指向你的 fops 表
    struct list_head list;
    dev_t dev;                           // 设备号（major:minor）
    unsigned int count;
};
```

`cdev` 的本质：把**设备号 `dev`** 和**操作表 `ops`** 绑定。

## 三、注册三步

```c
alloc_chrdev_region(&dev_num, 0, 1, "hello_dev");   // ① 动态申请设备号
cdev_init(&hello_cdev, &hello_fops);                // ② 绑定 fops
cdev_add(&hello_cdev, dev_num, 1);                  // ③ 注册进 cdev_map
```

`cdev_add`（fs/char_dev.c:479）内部调 `kobj_map(cdev_map, dev, ...)`——把"设备号 → cdev"存进全局 `cdev_map`。

## 四、设备号机制（major:minor）

- `dev_t` = 32 位，高 12 位 major、低 20 位 minor
- `MAJOR(dev)` / `MINOR(dev)` 宏拆解
- 设备号是"**文件节点 ↔ 驱动**"的关联键：`mknod` 在文件系统建节点记下 `(major, minor)`，open 时内核用它去 `cdev_map` 查 cdev
- 两边必须一致，否则 `ENXIO`（No such device or address）

## 五、数据流闭环（接回 VFS 多态）

```
用户态 open("/dev/hello_dev")
  → do_sys_openat2 → pathwalk 找到 inode（S_ISCHR）
  → chrdev_open(inode, filp)              ← fs/char_dev.c:373
      ├─ kobj_lookup(cdev_map, inode->i_rdev)  ← 设备号找 cdev，找不到→-ENXIO
      ├─ fops = p->ops                    ← 拿到驱动的 file_operations
      ├─ replace_fops(filp, fops)         ← file->f_op = 你的 fops（多态落地）
      └─ filp->f_op->open(inode, filp)    ← 调驱动的 open

用户态 read(fd, buf, n)
  → vfs_read → filp->f_op->read           ← 你的 read
      └─ copy_to_user(buf, msg, len)      ← 内核 → 用户态
```

这正是 `03-filesystem/06` 里 `f->f_op = inode->i_fop` 多态在字符设备侧的落地。

## 六、read 的 EOF 处理（最经典陷阱）

```c
static ssize_t hello_read(struct file *file, char __user *buf,
                          size_t len, loff_t *off) {
    int msg_len = strlen(msg);
    if (*off >= msg_len) return 0;          // 读完 → 返回 0 = EOF
    if (len > msg_len - *off) len = msg_len - *off;
    if (copy_to_user(buf, msg + *off, len)) return -EFAULT;
    *off += len;
    return len;
}
```

`cat` 会反复调用 `read` 直到返回 0。必须用 `*off`（文件偏移）追踪读到哪里，读完返回 0，否则 cat 死循环。

## 七、实验验证

```bash
insmod hello_dev.ko
dmesg | tail                        # 看 major，如 major=510
mknod /dev/hello_dev c 510 0        # 建节点（major 必须一致）
cat /dev/hello_dev                  # → Hello from kernel!
```

## 八、踩坑记录

1. **major 对不上 → ENXIO**：`alloc_chrdev_region` 动态分配 major，`mknod` 必须用 dmesg 里打印的真实值（示例里的 240 只是占位符）。
2. **mknod File exists**：旧节点没删，mknod 不覆盖，需先 `rm`。
3. **`# cat` 是注释**：shell 里 `#` 开头整行被当注释，命令没执行。
4. **copy_to_user 方向**：read 用 `copy_to_user`（内核→用户），write 用 `copy_from_user`（用户→内核）。
5. **EOF**：read 读完必须返回 0，否则 cat 死循环。

## 九、延伸

- `write`：`copy_from_user` 反方向拷贝
- `ioctl`：`unlocked_ioctl` 处理控制命令
- `class_create` + `device_create`：让内核自动建 `/dev` 节点（省去手动 mknod）
- `alloc_chrdev_region` vs `register_chrdev_region`：动态分配 vs 指定静态设备号
