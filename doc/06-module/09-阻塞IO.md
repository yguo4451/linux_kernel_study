# 29. 阻塞 IO：wait_event 与 wake_up

> 阶段四第九课。把非阻塞 read 升级成阻塞 read：读操作在没数据时睡眠等待（`wait_event_interruptible`），写操作写入后唤醒（`wake_up_interruptible`）。这是真实设备驱动（串口、键盘、传感器）最常用的机制。

## 一、为什么需要阻塞 IO

之前的 `read` 是**非阻塞**的：没数据就返回 0（EOF）。这适合"内容固定"的设备，但真实设备是**数据来了才有得读**：

- `cat` 一个串口，数据还没来 → 进程应**睡眠等待**，而不是立刻 EOF 退出
- 串口收到数据 → **唤醒**睡眠进程 → 读走数据

## 二、关键 API（include/linux/wait.h）

```c
#include <linux/wait.h>

wait_queue_head_t wq;               // ① 等待队列头
init_waitqueue_head(&wq);           // ② 初始化（waitqueue 无下划线！）

wait_event_interruptible(wq, 条件)  // ③ 睡眠直到条件为真（可被信号打断）
wake_up_interruptible(&wq);         // ④ 唤醒所有睡眠进程
```

## 三、生产者-消费者模型

```c
struct hello_dev {
    struct cdev cdev;
    char buf[128];
    int id;
    int has_data;              // 有没有数据可读（标志）
    wait_queue_head_t wq;      // 等待队列
};

// read：消费者 —— 没数据睡眠，被唤醒后读
static ssize_t hello_read(struct file *file, char __user *buf,
                          size_t len, loff_t *off) {
    struct hello_dev *dev = file->private_data;
    int n;

    if (wait_event_interruptible(dev->wq, dev->has_data))  // 阻塞等数据
        return -ERESTARTSYS;

    n = strlen(dev->buf);
    if (n > len) n = len;
    if (copy_to_user(buf, dev->buf, n)) return -EFAULT;

    dev->has_data = 0;         // 读完清标志
    return n;
}

// write：生产者 —— 写数据 + 唤醒
static ssize_t hello_write(struct file *file, const char __user *buf,
                           size_t len, loff_t *off) {
    struct hello_dev *dev = file->private_data;

    if (len >= sizeof(dev->buf)) return -EINVAL;
    if (copy_from_user(dev->buf, buf, len)) return -EFAULT;
    dev->buf[len] = '\0';

    dev->has_data = 1;                  // 有数据了
    wake_up_interruptible(&dev->wq);    // 唤醒阻塞的 read
    return len;
}
```

## 四、实验（两个终端）

```bash
# 终端 A：
cat /dev/hello_dev0        # 卡住（睡眠等数据）

# 终端 B：
echo "hello from uart" > /dev/hello_dev0   # 写入唤醒

# 终端 A：立刻打印 "hello from uart"，然后再次阻塞，Ctrl+C 退出
```

现象解读：

```
cat 卡住       → read 在 wait_event 睡眠（阻塞）
数据出现       → write 的 wake_up 唤醒 read（唤醒）
^C             → wait_event_interruptible 被信号打断（interruptible）
```

## 五、为什么 cat 不自动退出

`cat` 会一直 read 直到 EOF（返回 0），但阻塞设备**永不返回 EOF**——它永远"等下一批数据"。所以 cat 打印完第一笔后又去读、又卡住，只能 Ctrl+C 退出。

**这不是 bug，是阻塞设备的正确语义**——真实串口 `cat /dev/ttyS0` 也这样。

## 六、关键理解

1. **睡眠不是忙等**：`wait_event_interruptible` 让进程进入 `TASK_INTERRUPTIBLE` 睡眠，**不占 CPU**。
2. **interruptible 的意义**：可被信号打断（Ctrl+C 能杀掉卡住的 cat），返回 `-ERESTARTSYS`。内核态不想被打断用 `wait_event`（无 interruptible）。
3. **条件要配合标志**：`wait_event(wq, has_data)` 里的条件 + `has_data` 标志，是"条件变量 + 互斥"的简化版。write 置标志再唤醒，read 醒后重新检查条件。

## 七、踩坑记录

1. **`init_swait_queue_head` vs `init_waitqueue_head`**：swait（simple wait queue）是另一套轻量 API（`swait_queue_head_t` + `swait_event`/`swake_up`），没有 interruptible 变体。别混用。
2. **`init_wait_queue_head`（有下划线）不存在**：正确是 `init_waitqueue_head`（waitqueue 一个词）。类型 `wait_queue_head_t` 有下划线，init 函数没下划线——历史命名不统一。
3. **缺 `<linux/wait.h>`**：`wait_event`/`wake_up`/`init_waitqueue_head` 都在这个头文件里，漏了报 implicit declaration。
