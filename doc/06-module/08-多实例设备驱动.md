# 28. 多实例设备驱动：container_of 与 private_data

> 阶段四第八课。把单实例字符设备升级成多实例：一个驱动管多个设备（如 4 个串口），理解 `container_of` 识别实例、`file->private_data` 记忆实例，以及每个实例的独立私有状态。

## 一、问题：一个驱动管多个设备

同一个 `file_operations`（一套 read/write），但每个设备有**独立的私有状态**。关键是每次 read/write 要知道"操作的是哪个实例"。

## 二、两个核心机制

### 1. container_of：从成员指针反推外层结构体

```c
struct hello_dev {
    struct cdev cdev;    // 内嵌 cdev
    char buf[128];
    int id;
};
static struct hello_dev hello_devs[2];
```

`chrdev_open` 把找到的 `cdev` 存进 `inode->i_cdev`。驱动用 `container_of` 从 `i_cdev`（指向 `hello_devs[i].cdev`）反推出外层的 `hello_devs[i]`：

```c
struct hello_dev *dev = container_of(inode->i_cdev, struct hello_dev, cdev);
```

因为 `cdev` 在 `struct hello_dev` 中的偏移是编译期已知的，编译器算出外层结构体起始地址。这是内核**无处不在**的宏。

### 2. file->private_data：记忆实例

```c
static int hello_open(struct inode *inode, struct file *file) {
    struct hello_dev *dev = container_of(inode->i_cdev, struct hello_dev, cdev);
    file->private_data = dev;   // 记住"这次打开的是哪个实例"
    return 0;
}
```

之后 `read`/`write`/`ioctl` 通过 `file->private_data` 取回实例，操作它自己的数据：

```c
static ssize_t hello_read(struct file *file, char __user *buf,
                          size_t len, loff_t *off) {
    struct hello_dev *dev = file->private_data;   // 取回实例
    // 用 dev->buf，而不是全局 buf
    ...
}
```

## 三、注册循环

```c
static int __init hello_dev_init(void) {
    int i;
    alloc_chrdev_region(&dev_num, 0, 2, "hello_dev");   // count=2，2 个设备号
    cls = class_create("hello_dev");
    for (i = 0; i < 2; i++) {
        hello_devs[i].id = i;
        snprintf(hello_devs[i].buf, sizeof(hello_devs[i].buf),
                 "Hello from device %d!\n", i);          // 各自独立初始内容
        cdev_init(&hello_devs[i].cdev, &hello_fops);     // 同一个 fops
        cdev_add(&hello_devs[i].cdev, dev_num + i, 1);   // minor 0 和 1
        device_create(cls, NULL, dev_num + i, NULL, "hello_dev%d", i); // 两个节点
    }
    return 0;
}
```

## 四、数据流

```
cat /dev/hello_dev0
  → chrdev_open 用 (major,0) 找到 hello_devs[0].cdev
  → open: container_of 反推 &hello_devs[0] → 存进 private_data
  → read: 取回 &hello_devs[0] → 只操作它的 buf
  → 返回 0 号设备的内容
```

## 五、实验验证

```bash
insmod hello_dev.ko
ls /dev/hello_dev*          # 两个节点自动出现

cat /dev/hello_dev0         # Hello from device: 0
cat /dev/hello_dev1         # Hello from device: 1

echo "AAA" > /dev/hello_dev0
echo "BBB" > /dev/hello_dev1
cat /dev/hello_dev0         # AAA（互不干扰）
cat /dev/hello_dev1         # BBB
```

如果 device0 读到了 device1 的内容，说明 `private_data` 取回逻辑有 bug。

## 六、连接真实驱动（8250 串口）

Linux 标准串口驱动 `drivers/tty/serial/8250/` 就是这套模式：

- 每个串口一个 `struct uart_port`（存寄存器基址 `iobase`、中断号 `irq` 等）
- probe 时从设备树 `reg`/`interrupts` 属性填充每个 `uart_port`
- 运行时 `open("/dev/ttyS2")` → 找到对应 `uart_port` → 操作它的 `iobase`

内核只负责"路由"（设备号 → 实例），"这个实例操作哪个 IO"是驱动 init 时从硬件描述读来、存进实例结构体的。

## 七、踩坑

1. **`write` 里残留全局 `kernel_buf`**：改多实例后所有全局 buffer 都要换成 `dev->buf`，漏一处就会串数据。
2. **`alloc_chrdev_region` 的 count**：从 1 改成 N，一次申请 N 个连续设备号。
3. **`device_create` 名字**：用 `"hello_dev%d"` 格式串，否则两个节点同名会冲突。
