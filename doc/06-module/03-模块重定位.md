# 23. 模块重定位：定址、定符号、改写引用

> 阶段四第三课。深入 `load_module()` 里的三个重定位步骤：`layout_and_allocate`（确定段地址）、`simplify_symbols`（改写符号值）、`apply_relocations`（改写代码里的引用），并落到 arm64 的指令级重定位。

## 一、为什么是三步

```
layout_and_allocate()    → 确定每个段"住哪"（地址）
        ↓
simplify_symbols()       → 确定每个符号"指向哪"（符号值）
        ↓
apply_relocations()      → 把代码里对符号的引用"改成真值"（写入）
```

顺序不能乱：先有段地址，才能算符号地址；先有符号地址，才能算引用值。

## 二、Step1：layout_and_allocate —— 给段分配家

`kernel/module/main.c:2380`。核心 `__layout_sections()` 用一张 masks 表把 `.ko` 里的段**按权限分类**：

```c
static const unsigned long masks[][2] = {
    { SHF_EXECINSTR | SHF_ALLOC, ARCH_SHF_SMALL },    // 代码    → MOD_TEXT
    { SHF_ALLOC, SHF_WRITE | ARCH_SHF_SMALL },        // 只读数据 → MOD_RODATA
    { SHF_RO_AFTER_INIT | SHF_ALLOC, ARCH_SHF_SMALL },// ro_after_init → MOD_RO_AFTER_INIT
    { SHF_WRITE | SHF_ALLOC, ARCH_SHF_SMALL },        // 可写数据 → MOD_DATA
    { ARCH_SHF_SMALL | SHF_ALLOC, 0 }                 // 小数据  → MOD_DATA
};
```

这正是 `readelf -S` 里 flags 的用途：

| 段 | flags | 分到 |
|---|---|---|
| `.text` | AX | `MOD_TEXT` |
| `.rodata.str1.8` | AMS（无 W） | `MOD_RODATA` |
| `.data` / `.bss` | WA | `MOD_DATA` |

**关键设计**：模块内存按"类型"整块分配，不是每段单独一块——代码页 RX、数据页 RW、只读页 R，才能给不同块设不同页权限。

`module_get_offset_and_type()` 计算段在块内的偏移，并**复用 `sh_entsize` 字段**暂存"偏移 + 类型"（这个字段在模块加载时本来没用）。随后 `move_module()` 真正分配内存、`memcpy` 段内容、更新 `shdr->sh_addr` 为内核真实地址。

## 三、Step2：simplify_symbols —— 符号值改绝对地址

`kernel/module/main.c:1394`。按 `st_shndx` 分三种：

```c
case SHN_UNDEF:                       // 未定义符号，如 _printk
    ksym = resolve_symbol_wait(mod, info, name);
    sym[i].st_value = kernel_symbol_value(ksym);   // 改成内核真实地址
    break;
case SHN_ABS:                          // 绝对值符号，不动
    break;
default:                               // 定义在本模块某段里
    sym[i].st_value += secbase;         // 段基址 + 段内偏移 = 绝对地址
    break;
```

- `U _printk` → `resolve_symbol_wait()` 去内核 `__ksymtab` 查 → 得到 `_printk` 真实地址
- `hello_init`（在 `.init.text`）→ `st_value += .init.text 的基址`

## 四、Step3：apply_relocations —— 改写引用

`kernel/module/main.c:1472`。遍历所有 `SHT_RELA` 段（`.rela.text` 等），交给架构层 `apply_relocate_add()`：

```c
// arch/arm64/kernel/module.c:218
loc = 段地址 + rel[i].r_offset;        // 要改写的位置 P
sym = 符号表[ELF64_R_SYM(r_info)];     // 引用的符号
val = sym->st_value + rel[i].r_addend; // S + A（符号地址 + 加数）
// 按 r_type 把 val 写进 loc
```

对 `printk` 的调用是 **`R_AARCH64_CALL26`**（`bl` 指令，26 位有符号偏移）：

```
加载前：bl  0x000000        ← 目标还是占位 0
加载后：bl  _printk         ← 改写成"到 _printk 的相对偏移"
```

`val = S + A` 是 AArch64 ELF 规范：`S` 符号地址、`A` addend。arm64 用 **RELA**（重定位项自带 addend，每条 24 字节）；x86-32 用 REL（addend 存在被重定位的位置里）。

## 五、arm64 重定位类型速览（arch/arm64/kernel/module.c）

| 类型 | 含义 | 改写方式 |
|------|------|----------|
| `R_AARCH64_CALL26` | `bl` 函数调用 | 相对偏移写进 imm26 |
| `R_AARCH64_ABS64` | 64 位绝对地址 | 直接写 8 字节 |
| `R_AARCH64_ADR_PREL_PG_HI21` | `adrp` 页高21位 | `reloc_insn_adrp()` |
| `R_AARCH64_ADD_ABS_LO12_NC` | `add` 页内低12位 | imm12 写进指令 |

## 六、数据流全景

```
readelf -S 看到的 .ko（地址全 0）
        │
layout_and_allocate    → .text/.data 搬到 vmalloc 区，sh_addr 变真实地址
        │
simplify_symbols       → U printk → 内核地址；hello_init → 段内偏移→绝对地址
        │
apply_relocations      → 遍历 .rela.*，把 bl 指令的 imm26 改成真实相对偏移
        │
do_init_module         → 所有地址都对了，才敢调 module->init()
```

```bash
# 宿主机容器内看重定位表

# 预期看到 .rela.text 里对 printk 的 R_AARCH64_CALL26 条目
```

对照 `lsmod` 里 `hello` 的起始地址，`.text` 就在它附近——这就是 `layout_and_allocate` 亲手分配的"家"。
