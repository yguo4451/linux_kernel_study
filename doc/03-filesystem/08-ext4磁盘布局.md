# ext4 磁盘布局：从 inode 号到物理块

> 文件系统子系列第 8 篇（收官）。doc 04~07 讲的都是**内存里的 VFS 抽象**（inode/dentry/file），本篇把抽象落回**磁盘真实字节**：`ls -li` 看到的 inode 号 15，怎么换算成磁盘上的物理块。配套 `dumpe2fs`/`debugfs` 实测已跑通。

## 一、磁盘布局总览：块组（block group）

ext4 把磁盘切成一串**块组**，每个块组内部结构相同：

```
整个磁盘
├─ 块组 0
│    ├─ 超级块 superblock        (块0偏移1024字节，仅块组0有主副本)
│    ├─ 组描述符表 GDT           (每个块组一个 desc)
│    ├─ 块位图 block bitmap      (标记本组哪些块空闲)
│    ├─ inode 位图 inode bitmap  (标记本组哪些 inode 空闲)
│    ├─ inode 表 inode table     (本组所有 inode，每个 256 字节)
│    └─ 数据块 data blocks
├─ 块组 1  [超级块备份][GDT备份][块位图][inode位图][inode表][数据块]
└─ 块组 2 ...
```

思想：**元数据和数据分开、按组分散**，局部性好，也便于损坏恢复（备份超级块）。

## 二、超级块：`struct ext4_super_block`（`fs/ext4/ext4.h:1298`）

```c
struct ext4_super_block {
	__le32	s_inodes_count;		// inode 总数
	__le32	s_blocks_count_lo;	// 块总数
	__le32	s_log_block_size;	// 块大小 = 1024 << log
	__le32	s_blocks_per_group;	// 每组块数
	__le32	s_inodes_per_group;	// 每组 inode 数
	__le16	s_magic;		// ★ 0xEF53 魔数
	__le16	s_inode_size;		// inode 大小（默认 256）
	...
};
```

## 三、块组描述符：`struct ext4_group_desc`（`fs/ext4/ext4.h:389`）

```c
struct ext4_group_desc {
	__le32	bg_block_bitmap_lo;	// 块位图位置
	__le32	bg_inode_bitmap_lo;	// inode 位图位置
	__le32	bg_inode_table_lo;	// ★ inode 表位置
	__le16	bg_free_blocks_count_lo;
	__le16	bg_free_inodes_count_lo;
	...
};
```

**inode 号 → 磁盘位置** 就靠它：

```
块组号   = (inode - 1) / s_inodes_per_group
组内索引 = (inode - 1) % s_inodes_per_group
字节偏移 = group_desc[组号].bg_inode_table × 块大小 + 组内索引 × inode 大小(256)
```

## 四、磁盘 inode 与 extent：`struct ext4_inode` + `struct ext4_extent`

```c
struct ext4_inode {              // fs/ext4/ext4.h:765
	__le16	i_mode;          // 类型+权限
	__le32	i_size_lo;       // 文件大小
	__le16	i_links_count;   // 硬链接数
	__le32	i_block[EXT4_N_BLOCKS]; // 15 个块指针（老式间接块）
	...
};

struct ext4_extent {             // fs/ext4/ext4_extents.h:63
	__le32	ee_block;    // 文件逻辑块号
	__le16	ee_len;      // 连续块数
	__le32	ee_start_lo; // 物理块号
};
```

现代 ext4 默认用 **extent（区段）**：一个 extent 表达"文件逻辑块 [ee_block, +ee_len) → 物理块 [ee_start, ...)"，比逐块间接指针紧凑高效。

## 五、目录项：`struct ext4_dir_entry_2`（`fs/ext4/ext4.h:2319`）

```c
struct ext4_dir_entry_2 {
	__le32	inode;      // ★ 指向的 inode 号
	__le16	rec_len;    // 本条总长
	__u8	name_len;
	__u8	file_type;
	char	name[EXT4_NAME_LEN];  // 文件名
};
```

doc 05 pathwalk 的 `lookup_slow` 最终读的就是它：在目录数据块里线性扫描，匹配名字，拿到 inode 号。

### 块组布局（`dumpe2fs`）

```

  Primary superblock at 0
  Block bitmap at 65
  Inode bitmap at 69
  Inode table at 73-584        ← 512 块 = 8192 inode × 256B ✓
```

### inode 15 的 extent（`debugfs stat a.txt`）

```
Inode: 15   Type: regular   Mode: 0644
Links: 2    Blockcount: 8   Size: 6
EXTENTS:
(0):33280
```

对照：

| 输出 | 字段 | 含义 |
|------|------|------|
| `Links: 2` | `i_links_count` | 硬链接数=2（doc 04 的 a.txt+b.txt） |
| `Size: 6` | `i_size_lo` | "hello\n" 6 字节 |
| `Blockcount: 8` | `i_blocks` | 8×512B=4096B=1 块 |
| `(0):33280` | `ext4_extent` | 逻辑块0 → 物理块33280 |

### inode 号 → 磁盘位置（真实数字）

```
inode 15：块组号=0，组内索引=14
inode 表起始块=73
磁盘字节偏移 = 73 × 4096 + 14 × 256 = 302592 字节
```

inode 15 的元数据在磁盘第 302592 字节，其 extent 说"数据在物理块 33280"。

## 七、五篇串起来的完整链路

```
cat a.txt
  → pathwalk：查目录块 ext4_dir_entry_2，匹配 "a.txt" → inode 15
  → inode 15 → 块组0 inode 表偏移 302592 → struct ext4_inode
  → extent 表 = (0):33280 → 数据在物理块 33280
  → filemap_read 读块 33280 进页缓存
  → copy_to_user 拷给用户
```

**内存抽象（inode/dentry/file）→ 磁盘真实字节（块组/inode表/extent），彻底打通。**

## 八、要点总结

1. **磁盘 = 块组序列**，每组含 超级块/GDT/块位图/inode位图/inode表/数据块。
2. **超级块 s_magic=0xEF53** 是挂载时识别 ext4 的关键。
3. **inode 号 → 磁盘位置**：`(ino-1)` 除/模 `s_inodes_per_group` 定位块组和索引，再查 GDT 的 inode 表。
4. **extent 取代间接块**：`(逻辑块, 长度, 物理块)` 三元组表达连续数据。
5. **目录 = 线性 ext4_dir_entry_2 条目**，pathwalk 靠它做名字→inode 的映射。
